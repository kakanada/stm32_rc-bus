# rc_bus — настройка CubeMX

Развёрнутое описание каждой значимой настройки периферии для `rc_bus.h`/`rc_bus_telemetry.h`.
Таблица в `README.md` (раздел "Требования к настройке в CubeMX") — краткая сводка; при
расхождениях ориентируйтесь на `.h`-файлы (`rcbus_check_uart_settings()`/
`rcbus_telemetry_check_uart_settings()`) — они первичны, этот файл их пересказ для настройки
периферии ДО вызова `RCBUS_Init()`/`RCBUS_TelemetryInit()`.

## Приём каналов (`rc_bus.h`) — общие настройки для всех трёх протоколов

| Параметр CubeMX | Диапазон | Рекомендуемое значение для rc_bus | Пояснение |
|---|---|---|---|
| Mode | Asynchronous / Half-Duplex Selection | любое из двух, на выбор | `rc_bus.h` только принимает каналы (кроме исходящей телеметрии CRSF — см. ниже), поэтому `RCBUS_Init()` не проверяет и не требует конкретного режима: `HAL_UARTEx_ReceiveToIdle_DMA()` работает одинаково в обоих случаях. Выбирайте по тому, как разведена линия у приёмника — раздельные RX/TX или один общий провод (см. "Half-Duplex" ниже). |
| DMA Settings → Rx: DMA Mode | Normal / Circular | **Normal** | Обязательно Normal. Библиотека сама перезапускает приём после каждого кадра (`rcbus_restart_reception()`), ей нужен однократный приём "до простоя линии" (`HAL_UARTEx_ReceiveToIdle_DMA`), а не непрерывный кольцевой поток — Circular даст неверное определение границы кадра. |
| DMA Settings → Rx: Direction | Peripheral To Memory (фиксировано для Rx) | как задано CubeMX | Меняется автоматически при добавлении DMA-запроса на Rx — трогать не нужно. |
| NVIC Settings → USARTx global interrupt | Enabled / Disabled | **Enabled** | Обязательно. Определение простоя линии (IDLE, граница кадра) и ошибок (framing/noise/overrun) работает через прерывание USART, а не только через DMA — без этого `HAL_UARTEx_RxEventCallback()`/`HAL_UART_ErrorCallback()` не будут вызываться вообще, даже если байты физически приходят и DMA их принимает в буфер. |

## Приём каналов — параметры линии по протоколу

### i-BUS

| Параметр CubeMX | Диапазон | Значение для rc_bus | Пояснение |
|---|---|---|---|
| Baud Rate | произвольный | **115200** | Фиксированная скорость протокола FlySky i-BUS — приёмник всегда шлёт на этой скорости, менять нельзя. |
| Word Length | 8 Bits / 9 Bits | **8 Bits** | Стандартный байт данных, без дополнительного бита чётности в составе слова. |
| Parity | None / Even / Odd | **None** | У i-BUS нет бита чётности на уровне UART. |
| Stop Bits | 0.5 / 1 / 1.5 / 2 | **1** | Стандартный стоп-бит кадра UART i-BUS. |

### S.BUS

| Параметр CubeMX | Диапазон | Значение для rc_bus | Пояснение |
|---|---|---|---|
| Baud Rate | произвольный | **100000** | Фиксированная скорость протокола Futaba S.BUS. |
| Word Length | 8 Bits / 9 Bits | **9 Bits** | S.BUS физически передаёт 8 бит данных + 1 бит чётности — на уровне регистра STM32 USART это одно 9-битное слово (чётность входит в счёт бит слова в HAL, а не добавляется поверх 8-битного). Поставить 8 Bits здесь — частая ошибка, кадры не будут приниматься/будут битыми. |
| Parity | None / Even / Odd | **Even** | Бит чётности обязателен по протоколу S.BUS — без него `rcbus_check_uart_settings()` вернёт отказ в `RCBUS_Init()`. |
| Stop Bits | 0.5 / 1 / 1.5 / 2 | **2** | S.BUS использует 2 стоп-бита (увеличенный межсимвольный интервал для совместимости со старой Futaba-аппаратурой). |
| UART Advanced Features → Rx Pin Active Level Inversion (только STM32H7) | Disable / Enable | **Enable** | S.BUS физически инвертирован (логический 0 — это физическая "1" на линии). На H7 периферия умеет инвертировать сигнал аппаратно этим битом. |
| Внешний аппаратный инвертор (НЕ настройка CubeMX, только для STM32F4) | — | транзисторный ключ между линией приёмника и ногой RX МК | На "классическом" F4 (в т.ч. F446) в USART физически нет регистра инверсии — программной альтернативы нет в принципе (периферия ищет старт-бит уже на неинвертированном аппаратно сигнале). Без инвертора S.BUS на F4 приниматься не будет. Если приёмник поддерживает и CRSF — проще выбрать CRSF (см. ниже), инвертор не понадобится вообще. |

### CRSF

| Параметр CubeMX | Диапазон | Значение для rc_bus | Пояснение |
|---|---|---|---|
| Baud Rate | произвольный | **420000** | Фиксированная скорость протокола CRSF (TBS Crossfire/ExpressLRS). |
| Word Length | 8 Bits / 9 Bits | **8 Bits** | Как у i-BUS — без бита чётности. |
| Parity | None / Even / Odd | **None** | У CRSF нет бита чётности. |
| Stop Bits | 0.5 / 1 / 1.5 / 2 | **1** | Стандартный стоп-бит. |
| Инверсия сигнала | — | **не требуется** | CRSF физически не инвертирован ни на F4, ни на H7 — именно поэтому это самый простой в подключении из трёх протоколов на F4 (не нужен внешний инвертор, обязательный для S.BUS). |

## Half-Duplex Selection — если у приёмника один общий провод на канал

Применимо к любому из трёх протоколов (чаще всего нужно для CRSF-приёмников с одним пином
вместо раздельных RX/TX), настраивается в дополнение к параметрам линии выше.

| Параметр CubeMX | Диапазон | Значение для rc_bus | Пояснение |
|---|---|---|---|
| Mode | Half-Duplex Selection | выбрать (вместо Asynchronous) | В этом режиме периферия и передаёт, и принимает через один и тот же пин **TX** — нога RX физически не используется. Провод приёмника подключается к ноге TX МК, а не RX (частая ошибка подключения). |
| GPIO Settings (для пина TX) → GPIO mode | Output Open Drain (CubeMX ставит сам при выборе Half-Duplex) | **Open Drain** | Открытый сток обязателен для однопроводной линии: два активных push-pull-передатчика на одном проводе дали бы короткое замыкание логических уровней, когда оба молчат (приёмник держит "1", а передатчик МК тоже пытается держать "1"/"0" пуш-пулом). Open Drain МК только притягивает линию к земле, никогда не "толкает" её вверх сам. |
| GPIO Settings (для пина TX) → Pull-up/Pull-down | No pull-up and no pull-down / Pull-up / Pull-down | **Pull-up** | Open Drain не может сам поднять линию в "1" — для этого нужен подтягивающий резистор. Внутренний Pull-up МК (~40 кОм) обычно достаточен для короткого провода до приёмника; без него (и без внешнего резистора на плате приёмника) уровень линии в режиме ожидания не определён, и периферия не видит валидного старт-бита — приём молчит (ни кадров, ни ошибок). |

`RCBUS_Init()` сам переводит линию в режим "только приём" (`HAL_HalfDuplex_EnableReceiver()` —
сбрасывает `TE`, выставляет `RE`) при каждом (пере)запуске приёма, чтобы собственный
передатчик МК не держал линию в состоянии "mark" и не забивал сигнал приёмника — отдельно
настраивать в CubeMX для этого ничего не нужно.

## Исходящая телеметрия CRSF (`RCBUS_CRSF_SendFrame()`/`RCBUS_CRSF_SendBatteryTelemetry()`)

Используется тот же `huart`, что и для приёма каналов CRSF — отдельной настройки периферии
не требует, кроме следующего:

| Параметр CubeMX | Диапазон | Значение для rc_bus | Пояснение |
|---|---|---|---|
| DMA Settings → Tx | добавлять / не добавлять | **не добавлять** | Передача идёт через `HAL_UART_Transmit_IT()` (по прерыванию, без DMA) — отдельный DMA-канал на передачу не нужен. |
| Нога TX МК (при Mode = Asynchronous) | подключена / не подключена | **подключить** к соответствующему входу приёмника | Если линия асинхронная (раздельные RX/TX) и вы собираетесь отправлять телеметрию — без физического подключения TX МК к приёмнику кадры будут "уходить в никуда". Если линия Half-Duplex — отдельно подключать нечего, передача и так идёт через тот же провод. |

## Телеметрия i-BUS (`rc_bus_telemetry.h`) — отдельная физическая линия

Это другой, самостоятельный `huart` — не тот же, на котором `rc_bus.h` принимает каналы.

| Параметр CubeMX | Диапазон | Значение для rc_bus_telemetry | Пояснение |
|---|---|---|---|
| Mode | Asynchronous / Half-Duplex Selection | **Half-Duplex Selection** (обязательно) | Единственный протокол в этой библиотеке, для которого Half-Duplex жёстко обязателен (не на выбор): шина "SENSOR" i-BUS физически однопроводная, а модуль ещё и отвечает на той же линии, где принимает опрос — `rcbus_telemetry_check_uart_settings()` явно проверяет бит `CR3.HDSEL` и вернёт `NULL` из `RCBUS_TelemetryInit()`, если Half-Duplex не включён (частая ошибка — забыли выбрать и получили обычный `HAL_UART_Init()`). |
| Baud Rate | произвольный | **115200** | Скорость шины датчиков i-BUS SENSOR. |
| Word Length | 8 Bits / 9 Bits | **8 Bits** | Без бита чётности. |
| Parity | None / Even / Odd | **None** | У шины SENSOR нет бита чётности. |
| Stop Bits | 0.5 / 1 / 1.5 / 2 | **1** | Стандартный стоп-бит. |
| DMA Settings → Rx: DMA Mode | Normal / Circular | **Normal** | Та же причина, что и для приёма каналов — однократный приём "до простоя линии". |
| NVIC Settings → USARTx global interrupt | Enabled / Disabled | **Enabled** | Нужен и для приёма опроса (IDLE/ошибки), и для `HAL_UART_TxCpltCallback()` при отправке ответа. |
| GPIO Settings (для пина TX) → GPIO mode / Pull-up | Open Drain / Pull-up (CubeMX ставит сам при Half-Duplex) | **Open Drain + Pull-up** | Та же причина, что и для Half-Duplex на `rc_bus.h` выше — однопроводная линия, оба устройства (МК и приёмник) по очереди говорят на одном проводе. |
